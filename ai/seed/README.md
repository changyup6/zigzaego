# seed — 범용 재료표

`ingredient_catalog.csv` 는 온보딩 재료 분류(지라 100)가 **LLM 보다 먼저** 보는 표다.
구성 추출이 낸 재료 이름이 이 표의 이름이나 별칭과 맞으면 표 값을 쓰고, 맞지 않는 재료만 LLM(`prompts/onboarding/ingredient_classify.md`)에 묻는다.

**값은 전부 일반 상식에 기댄 추정이다.** 특정 가게의 레시피가 아니고, 측정한 값도 아니다.
1인분 초기값은 질문의 가운데 보기로만 쓰이고 사장님 답이나 레시피 파일이 들어오면 바뀐다.

## 열

| 열 | 뜻 |
|---|---|
| `name` | 대표 이름. 구성 추출 결과에 그대로 쓰기를 권하는 표기 |
| `aliases` | 같은 재료의 다른 표기, `;` 로 구분. 비교는 공백을 빼고 소문자로 |
| `kind` | `BOM`(섞어 만드는 메뉴의 재료) · `ONE_TO_ONE`(사 온 그대로 파는 품목, 1인분 = 1) |
| `unit` | DB 기준 단위 `G` · `ML` · `EA` |
| `storage_type` | `FROZEN` · `AMBIENT` · `CHILLED` · `FRESH` (백엔드 `StorageType` 과 같은 값) |
| `per_serving` | 1인분 초기값, `unit` 기준 |
| `confidence` | 초기값을 얼마나 믿나 (0~1). **0.7 미만이면 질문 대상** (`questions.py`) |
| `shelf_life_days` | 개봉 전 업소 보관 기준 유통기한(일), 2 이상 정수. `storage_type` 으로 보관할 때 기준 |

## 단위 규칙 (설계 §3)

- 1인분을 **개 · 마리로 세면 `EA`** (새우 5마리, 계란 1개, 캔 음료)
- **가루 · 장류 · 고기 · 채소는 `G`** (고추장, 대파, 베이컨, 치즈)
- **액체는 `ML`** (우유, 식용유, 간장)

## 유통기한 (`shelf_life_days`)

**이 값도 측정이 아닌 추정이다.** 업소용으로 흔히 들어오는 포장을 뜯기 전, `storage_type` 대로 보관할 때를 기준으로 짧은 쪽(보수적)으로 잡았다.
대략 생 채소 · 허브 3~7일, 생고기 3일, 냉장 유제품 · 가공육 7~30일, 냉동품 90~180일, 건면 · 통조림 · 병 소스 · 기름 · 캔 음료 180~365일.
설계 5.3 대로 재료별 값이 기본이고, **보관 방식 표(101)의 값은 재료별 값이 없을 때만 쓰는 후보값이다.** 표에 없는 재료는 분류 프롬프트(`shelfLifeDays`)가 채운다.

## 확신도를 고른 방식

- 가게마다 양이 크게 갈리는 주재료(면 · 고기 · 새우)는 0.5 — 늘 질문한다
- 양이 조금 갈리는 부재료는 0.6~0.7
- 양념 · 고명처럼 작게 들어가 틀려도 발주에 영향이 작은 것은 0.8 이상
- 1:1 음료는 0.9 이상

재료를 더하거나 값을 바꾸면 `tests/test_onboarding_catalog.py` 가 이름 · 별칭 충돌과 값 범위를 검사한다.
