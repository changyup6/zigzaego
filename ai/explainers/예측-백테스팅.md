# 예측 백테스팅 — 어떤 예측이 판매량을 잘 맞히는지 숫자로 재기

## 한 문장

**지난 8주를 다시 살아 보며 세 가지 예측 방법이 판매량을 얼마나 맞혔는지 같은 자로 재고, 서비스에서 내린 TimesFM 을 다시 쓸 근거가 있는지 한 줄로 판정하는 곳입니다.**

코드는 `src/weglee_ai/backtest.py`, 실행은 `scripts/backtest_forecast.py`, 노트북은 `notebooks/03_backtest_forecast.ipynb`입니다. 지표 자체(WAPE · Bias)는 [평가 지표](평가-지표.md)에서 설명합니다.

## 왜 필요한가

처음에는 TimesFM 으로 매일 새벽 7일 판매를 예측하기로 했지만(DECISIONS #24), 지금은 TimesFM 을 서비스 예측에서 내렸고 발주 추천의 수요 예측은 요일 평균을 씁니다(DECISIONS #91). 이 도구는 그 결정이 실제 판매에서도 맞는지 숫자로 확인합니다. 더 무거운 TimesFM 이 요일 평균보다 확실히 낫지 않으면 다시 쓸 이유가 없습니다.

## 비교하는 세 가지

| 이름 | 어떻게 예측하나 | 왜 넣었나 |
|---|---|---|
| 감 (`last_week`) | 지난주 같은 요일에 팔린 만큼 | 사장님이 감으로 발주하는 방식. 이것보다 못하면 예측이 의미가 없다 |
| 요일 평균 (`dow_avg`) | 최근 4주 같은 요일 평균 | 지금 발주 추천이 쓰는 수요 예측이자 기준선 |
| TimesFM (`timesfm`) | TimesFM 2.5, 학습 없이 과거 계열만 넣어서 | #91 로 서비스에서 내린 후보. 다시 쓸 근거가 있는지 본다 (선택, `--timesfm`) |

## 어떻게 재나

```
평가 기간 = 데이터의 마지막 8주

평가 기간의 날마다 (기준일 t)
  t 까지의 판매만 보여 주고 t+1 ~ t+7 을 예측하게 한다
  예측과 실제를 (날짜, 배달 · 홀, 메뉴) 마다 비교한다
```

- **그날까지만 보여 줍니다.** 내일을 맞히는데 내일 판매를 보면 반칙이라, 기준일을 하루씩 옮기며 매번 그 이전 데이터만 넘깁니다
- **쉬는 날은 빼고, 문을 열었는데 안 팔린 메뉴는 0으로** 셉니다. 야간 배치와 같은 규칙입니다
- **다음 날(h = 1)이 기준**입니다. 서비스는 새벽 예측을 그날 발주에 씁니다. 7일 평균(h = 1~7)도 같이 봅니다 — 배송을 기다리는 동안의 소비도 예측에 기대기 때문입니다
- **배달과 홀을 더한 값(합계)으로 판정**합니다. 재료는 채널을 가리지 않고 줄어들기 때문입니다

## 판정 규칙

```
같은 행에서 TimesFM WAPE < 요일 평균 WAPE  → TimesFM 을 다시 쓸 근거 있음
그렇지 않으면                             → 요일 평균 유지
더 맞는데 TimesFM Bias 가 ±10% 를 넘으면    → 요일 평균 유지 (늘 많이 또는 늘 적게 예측하는 버릇)
실제 판매 합이 0                           → 판정 보류 (WAPE 를 잴 수 없다)
```

"같은 행"이 중요합니다. TimesFM 은 판매가 오래 끊긴 메뉴를 건너뛸 수 있어서, 그런 행은 요일 평균 쪽에서도 빼고 비교합니다. 한쪽만 쉬운 문제를 풀면 공정하지 않습니다.

## 결과 읽는 법

스크립트는 `outputs/backtest_forecast.md` 에 세 가지를 씁니다.

1. **결론 한 줄** — 예: "요일 평균 유지 — TimesFM 이 낫지 않다 (WAPE TimesFM 0.112 · 요일 평균 0.108, TimesFM Bias +0.003)"
2. **발표용 표** — 채널 합계 · 다음 날 기준, 모델 셋
3. **전체 표** — 모델 × 배달 · 홀 · 합계 × 다음 날 · 7일

샘플 데이터 결과는 판정에 쓰지 않습니다. 샘플은 요일 패턴에 일정한 흔들림을 섞어 만든 가상 데이터라, 어느 모델이 실제 가게에서 나은지는 알려 주지 않습니다. 계산이 끝까지 도는지 확인하는 용도입니다.
