# ADR-0019: 시연 계정의 가게는 오늘이 고정일이다 — 가게별 시계 `StoreClock` 으로 읽는다

- 상태: 채택
- 영역: backend · frontend
- 결정 로그: [DECISIONS #99](../DECISIONS.md)
- 관련 이슈: S15P31A308-337

## 맥락

- 발표 시연은 이번 주 매출 예측에서 11월 14일 잠실 경기로 매출이 뛰는 장면을 보여 준다. 시연하는 날이 그 주를 지나면 "이번 주"가 바뀌어 그 장면이 나오지 않는다.
- BE 의 "오늘"은 서비스마다 `Clock` 빈이나 `LocalDate.now(가게 시간대)` 로 따로 읽고 있었다. FE 도 기기 날짜로 오늘을 따로 계산했다.
- 다른 가게(팀 테스트 계정 · 실사용)의 날짜는 바뀌면 안 된다.

## 결정

- `StoreClock.of(storeId)` 가 가게의 시계를 준다. 시연 계정 이메일(`DEMO_ACCOUNT_EMAIL`, ADR-0018)에 연결된 가게면 날짜를 `app.demo-account.today`(`DEMO_ACCOUNT_TODAY`, 기본 `2026-11-12`)로 옮긴 시계, 아니면 `Clock` 빈 그대로다. 시각(시 · 분)은 실제 그대로 흐른다.
- 가게의 오늘 · 기록 시각을 읽는 서비스는 `Clock` 대신 `StoreClock` 을 쓴다: 매출 예측 · 메뉴 예측 · 추정 재고 · 재고 실사 · 마감 확인 · 발주 추천 · 발주서 · 입고 · 자동 입고 · 마감 알림 · 시세 · 단가 추이. 배치(추천 생성 · 자동 입고 · 마감 알림)도 가게 id 로 같은 시계를 읽으므로 시연 가게는 배치에서도 고정일이다.
- 시연 가게인지는 부를 때마다 `store_member` · `account` 로 조회한다. 다시 가입하면(ADR-0018) 이메일이 새 계정으로 넘어가므로 새 가게가 고정일을 받고, 보관된 옛 가게는 실제 날짜로 돌아간다.
- `GET /stores/me` 가 `today`(가게 시간대의 오늘, `YYYY-MM-DD`)를 준다. FE 는 기기 날짜 대신 이 값을 오늘로 쓴다(머리글 날짜 · 발주 내역의 이번 달 · 최근 7일 소비 · 오늘 실사 표시).
- 토큰 만료(JWT) · job · 영수증 인식 시각은 `Clock` · 실제 시각 그대로다.

## 버린 대안

| 대안 | 왜 안 골랐나 |
|---|---|
| `Clock` 빈 자체를 로그인한 계정에 따라 바꿈 | 토큰 만료 계산과 배치까지 같은 빈을 써서, 요청 문맥이 없는 곳에서 날짜가 달라지거나 토큰이 바로 만료된다 |
| FE 만 날짜를 고정 | 매출 예측 · 발주 추천 · 추정 재고의 기준일은 BE 가 정한다. 화면 날짜만 바뀌고 내용은 실제 오늘 기준으로 남는다 |
| 서버 전체 시각을 고정 | 같은 스테이징을 쓰는 다른 계정과 배치가 모두 영향을 받는다 |
| 날짜만 고정하고 기록 시각은 실제 시각 | 실사 · 입고 기록이 "오늘"보다 미래가 되어 추정 재고에 반영되지 않는다 |

## 결과

- **좋아지는 것**: 시연 계정은 언제 로그인해도 고정일 기준의 예측 · 추천 · 재고를 본다. 다른 가게는 달라지지 않는다. 오늘을 읽는 곳이 한 군데로 모였다.
- **감수하는 것**: 시연 설정이 있는 환경에서는 시계를 읽을 때마다 조회가 1번 늘어난다(설정이 없으면 조회하지 않는다). `created_at` 같은 DB 기본 시각 · 거래처 단가 직접 입력의 관측 시각 · job · 영수증 시각은 실제 시각이라 시연 가게에서는 고정일보다 뒤다. 시연 가게의 데이터(판매 · 예측)는 고정일에 맞춰 따로 넣어야 한다. 마감 알림은 영업일이 늘 같은 날이라 가게당 한 번만 간다.
- **다시 볼 시점**: 시연이 끝나면 `DEMO_ACCOUNT_EMAIL` 을 비운다(고정도 함께 꺼진다). 가게별 "가상 오늘"이 시연 밖에서도 필요해지면 가게 표의 열로 옮긴다.
