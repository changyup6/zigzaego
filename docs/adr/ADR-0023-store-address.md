# ADR-0023: 가게 전체 주소와 배송 시군구를 분리한다

- 상태: 채택
- 영역: backend · frontend
- 결정 로그: [DECISIONS #115](../DECISIONS.md)
- 관련 이슈: S15P31A308-357

## 맥락

더보기의 위치는 `store.sigungu`만 보여주어 네이버 플레이스에서 수집한 전체 주소가 사라진다.
시군구는 식자재몰 배송 가능 판정에 사용하는 정규화된 값이므로 전체 주소로 덮어쓸 수 없다.
검색 후보의 주소는 Apify 응답과 운영자가 저장한 SEARCH replay에 이미 있다.

## 결정

- Flyway V25로 `store.address TEXT NULL`을 추가하고 기존 시군구와 배송 판정은 유지한다.
- 가게 선택 시 서버가 받은 Apify 검색 후보의 주소를 같은 placeId로 찾아 현재 로그인한 가게에 저장한다.
- 실시간 검색 후보는 API 서버 메모리에 최대 500개/30분 보관한다. 찾지 못하면 운영자 SEARCH replay에서 placeId가 일치하는 후보를 찾는다.
- 클라이언트 주소는 받지 않는다. 주소 조회만을 위한 외부 재수집이나 일반 요청의 replay 영구 저장은 하지 않는다.
- 선택한 후보에 주소가 없으면 null로 저장한다. 다른 장소의 예전 주소를 그대로 남기지 않는다.
- `GET /stores/me`에 nullable `address`를 포함한다. 더보기 위치는 전체 주소 → 시군구 → `–` 순서로 표시한다.
- V25는 기존 가게의 `naver_place_id`와 일치하는 SEARCH 후보 중 최신의 비어 있지 않은 주소를 보강한다. 특정 가게 자료를 하드코딩하지 않고 시군구는 바꾸지 않는다.

## 버린 대안

| 대안 | 이유 |
|---|---|
| `sigungu`에 전체 주소 저장 | 배송 판정의 시군구 일치 계약을 깨뜨린다 |
| 요청 본문의 주소 저장 | 서버가 수집한 후보와 관계없는 주소를 신뢰하게 된다 |
| 주소를 위해 Apify를 다시 호출 | 검색에서 이미 받은 자료에 지연과 과금이 추가된다 |

## 결과

기존 가게와 이전 API 응답은 시군구 표시로 호환된다. API 서버 재시작·후보 만료 뒤 저장본이 없는
실시간 후보는 주소를 확인할 수 없어 null이 될 수 있다. 여러 API 서버를 쓰게 되면 후보 보관을 공유 저장소로 옮긴다.
