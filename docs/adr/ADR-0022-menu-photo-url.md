# ADR-0022: 메뉴 대표 사진 URL 저장과 표시

- 상태: 채택
- 영역: backend · frontend
- 결정 로그: [DECISIONS #45 · #114](../DECISIONS.md)
- 관련 이슈: S15P31A308-129

## 맥락

수집기는 메뉴 사진 URL을 받지만 분석 초안·확정 메뉴에서 버려져 레시피 화면에 사진이 나오지 않는다.
메뉴는 가게별로 저장되며 이름 변경·분석 재확정 뒤에도 사진 연결이 유지되어야 한다.

## 결정

- Flyway V24로 `menu.photo_url TEXT NULL`을 추가한다. 대표 사진 한 개의 원본 HTTP(S) URL을 저장한다.
- 수집한 사진 중 첫 유효 URL을 분석 초안의 `photoUrl`로 전달하고 확정 시 같은 가게의 메뉴에 저장한다.
- 사진 필드 없는 이전 분석 초안도 읽는다. 다시 확정할 때 사진이 없으면 기존 사진을 지우지 않는다.
- 분석 저장본에 사진이 빠져 있으면 같은 `placeId`의 메뉴 저장본에서 이름이 같은 사진을 보완한다. 메뉴 저장본이 없어도 외부 수집이나 LLM을 추가 호출하지 않는다.
- 메뉴 조회·레시피 응답에 nullable `photoUrl`을 포함한다. 사진 조회는 기존 메뉴의 `store_id` 범위를 따른다.
- 프론트는 URL을 목록·상세로 전달하고 기존 크기 안에서 비율을 유지해 표시한다. URL 없음·로드 실패는 기존 아이콘으로 대체한다.
- 외부 이미지는 브라우저에서 원본 URL로 읽는다. 서버 이미지 프록시·도메인별 하드코딩·별도 업로드 화면은 추가하지 않는다.

## 버린 대안

| 대안 | 이유 |
|---|---|
| 프론트에서 메뉴 이름별 사진 매핑 | 가게 간 같은 이름·이름 변경에 취약하고 사용자 데이터를 코드에 하드코딩하게 된다 |
| 조회마다 최신 분석 job에서 사진 추출 | 예전 분석 결과·수동 메뉴와 현재 메뉴 사이의 관계가 불안정하다 |
| 이미지 원본을 새 저장소로 복사 | 이번 수정에 별도 저장·서빙·수명 관리가 필요하지 않다 |

## 결과

기존 사진 없는 메뉴와 호환되며 메뉴 ID에 사진 연결이 남는다. 원본 출처의 URL 만료·접근 실패는
기본 아이콘으로 처리한다. 이미 확정된 메뉴는 가게 범위를 확인한 데이터 보강이나 재수집이 필요하다.
