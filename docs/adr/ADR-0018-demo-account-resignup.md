# ADR-0018: 시연 계정 이메일은 이미 가입돼 있어도 다시 가입된다 — 옛 계정은 지우지 않고 이메일만 보관용으로 바꾼다

- 상태: 채택
- 영역: backend
- 결정 로그: [DECISIONS #98](../DECISIONS.md)
- 관련 이슈: S15P31A308-337

## 맥락

- 발표 시연은 가입 → 온보딩 → 로그인을 처음부터 보여 준다. 리허설을 한 번 하면 그 이메일은 이미 가입돼 있어 `POST /auth/signup` 이 409 `AUTH_EMAIL_TAKEN` 으로 막힌다.
- 계정을 가입 전으로 되돌리려면 그 가게의 모든 표(재료 · 레시피 · 발주 · 판매 이력 …)를 지워야 한다. 표가 늘 때마다 지우는 순서를 맞춰야 하고, 잘못 지우면 되돌릴 수 없다.
- 시연 계정 이메일 · 비밀번호는 저장소에 두지 않는다.

## 결정

- 환경 변수 `DEMO_ACCOUNT_EMAIL`(`app.demo-account.email`)에 이메일 하나를 적는다. 비어 있으면 아무 것도 달라지지 않는다.
- 그 이메일로 `POST /auth/signup` 이 왔는데 계정이 이미 있으면, 옛 계정의 이메일을 `archived-<계정 id>-<이메일>` 로 바꿔 자리를 비운 뒤 평소대로 새 계정 · 새 가게를 만든다. 같은 트랜잭션이라 가입이 실패하면 이름 바꾸기도 되돌아간다.
- 옛 계정 · 가게 · 데이터는 지우지 않는다. 옛 계정은 보관용 이메일과 옛 비밀번호로 여전히 로그인된다.
- 로그인은 바꾸지 않는다. 시연 이메일로는 마지막에 가입한 계정(마지막 비밀번호)만 로그인된다.
- 이메일 비교는 계정 표의 unique 와 같은 기준(대소문자 구분, 앞뒤 공백 제거)이다.

## 버린 대안

| 대안 | 왜 안 골랐나 |
|---|---|
| 재가입 때 옛 계정 · 가게 데이터를 모두 삭제 | 가게에 딸린 표를 전부 순서대로 지워야 하고 표가 늘 때마다 고쳐야 한다. 실수하면 복구할 수 없다 |
| 운영자가 DB 에서 직접 초기화하는 절차만 문서로 | 시연 직전마다 사람이 DB 에 들어가야 하고, 리허설을 여러 번 하기 어렵다 |
| 시연 이메일은 가입할 때마다 비밀번호만 바꿔 같은 가게로 로그인 | 온보딩이 끝난 가게라 가입 뒤 온보딩 장면을 다시 보여 줄 수 없다 |

## 결과

- **좋아지는 것**: 시연 이메일로는 언제든 가입 → 온보딩을 처음부터 다시 할 수 있다. 지우는 코드가 없어 데이터를 잃을 일이 없다.
- **감수하는 것**: 이 이메일을 아는 사람은 누구나 다시 가입해 그 이메일의 로그인을 가져갈 수 있다. 새 가입은 빈 새 가게를 받으므로 옛 가게의 데이터는 보이지 않지만, 시연 중인 계정의 로그인이 새 계정으로 넘어간다 — 이메일은 팀 안에서만 공유하고 변수는 시연에 쓰는 환경에만 넣는다. 보관된 옛 계정 · 가게가 계속 쌓인다. 옛 계정이 받은 refresh token 은 만료 전까지 옛 가게로 유효하다.
- **다시 볼 시점**: 보관된 계정이 많아져 정리가 필요해지면 운영자용 지우기 실행을 따로 결정한다. 시연이 끝나면 변수를 비운다.
