# ADR-0001: GitLab 모노레포 1개

- 상태: 채택
- 영역: repo
- 결정 로그: [DECISIONS #15](../DECISIONS.md)
- 관련 이슈: S15P31A308-15 · S15P31A308-16

## 맥락

SSAFY GitLab은 팀에 프로젝트 1개를 준다. 6명이 FE · BE · AI · Infra로 나뉘어 3주 안에 만든다.
기획 문서, Jira 일감 생성 스킬, MR 자동화 파이프라인을 코드와 함께 버전 관리하려 한다.
레포를 영역별로 나누면 문서와 자동화를 레포 수만큼 복제해야 하고, 자동 개발 파이프라인이 "어느 레포인가"를 매번 탐색해야 한다.

## 결정

레포 하나에 전부 둔다.

```
docs/   frontend/   backend/   ai/   infra/   .claude/   .gitlab/   scripts/
```

- Jira 제목 접두어가 곧 작업 폴더다: `[FE]` → `frontend/`, `[BE]` `[DB]` → `backend/`, `[AI]` → `ai/`, `[INFRA]` → `infra/`, `[PM]` → `docs/`
- CI는 변경 경로(`changes:`)로 영역별 잡을 나눈다. 한 영역의 커밋이 다른 영역 빌드를 돌리지 않는다
- 브랜치는 `main`(릴리즈) + `develop`(통합) 둘. 영역별 통합 브랜치는 두지 않는다

## 버린 대안

| 대안 | 왜 안 골랐나 |
|---|---|
| 영역별 레포 3~4개 | `.claude/` · 문서 · 훅을 복제. 한 기능이 FE + BE에 걸칠 때 MR이 두 개로 갈려 리뷰가 어긋난다 |
| 문서 레포 + 코드 레포 | 결정이 바뀌면 코드와 문서를 같은 MR에 못 넣는다. stale 문서를 막을 장치가 사라진다 |

## 결과

- **좋아지는 것**: 설정 한 벌. 결정 · 문서 · 코드가 같은 MR. 파이프라인이 경로 탐색 없이 접두어로 폴더를 정한다
- **감수하는 것**: 레포가 커진다. CI `changes:` 필터를 잘못 쓰면 모든 잡이 돈다. 바이너리(`docs/submit/`)도 같은 히스토리에 들어온다
- **다시 볼 시점**: 영역별 배포 주기가 완전히 갈리거나, 외부 조직이 한 영역만 가져가야 할 때
