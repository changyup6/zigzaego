# ADR-0021: 가게에 가져온 가격은 가게별 표에서 비교한다

- 상태: 채택
- 영역: backend · frontend · ai
- 관련 이슈: S15P31A308-349 · S15P31A308-350

## 맥락

전역 `market_product`는 실제 수집 데이터다. 반복 가입 시연의 합성 가격을 넣으면 다른 가게도 보게 된다. 화면은 두 몰에 고정되어 실제 응답의 여러 후보와 날짜별 누락을 버리고 있었다.

## 결정

- V23 `store_market_quote`는 `(store_id, ingredient_id, site, collected_on)` 스냅샷이다. 복합 외래키가 다른 가게의 재료 연결을 거부한다. 가격은 **재료 기준 단위당 원**, 실제 포장 양·가격·상품명·규격·URL과 `synthetic`을 함께 저장하고 포장 가격 일치도 검사한다. 적재용 HTTP API나 자동 외부 수집은 추가하지 않는다.
- 기존 offers/history API는 가게별 행이 없으면 기존 응답을 그대로 준다. 있을 때만 전역 후보의 환산 가능한 값을 재료 기준 단위로 바꿔 합친다. 같은 사이트·수집일은 명시적으로 가져온 행이 우선한다. 미래 행을 제외한다. 가게별 행의 배송 가능은 적재자가 해당 가게에 대해 확인한 계약이다. 합성값은 응답과 화면에 구분한다.
- 명시적 시연 템플릿 준비의 선택 자산 `ai/seed/demo_market/pao-market-v1.sql`은 고정일 기준 2재료 × 4몰 × 8주, 64행이다. 이름·단위 일치와 건수를 검사하고 중복 적용은 upsert한다. -343의 준비/연결 도구가 지정된 시연 가게에만 원자적으로 연결한다. V23 배포 전에는 이 자산을 적용하지 않는다. 전역 표를 수정하지 않는다.
- FE는 모든 응답 후보의 단가·상품 포장 가격·배송 상태를 읽고, 같은 기준 단위로 환산한다. 당일 가격과 배송 가능이 확인된 후보만 추천/선택/절감 계산에 사용한다. 수집 누락은 0원으로 채우지 않는다.
- 주문서 source에 `MARKETBOM`, `ORDERLINK`를 더하고 실제 쿠팡 응답도 단가·URL을 저장한다. 당일 가격이 아닌 응답은 신규 주문 단가로 저장하지 않는다. 기존 쿠팡 검색 링크만 저장하는 요청 호환은 유지한다.
- **비교·절감액은 같은 추천 품목과 요청 수량 기준의 환산 금액이며 배송비를 제외한다.** 화면에 `기준 수량 환산 · 배송비 제외`를 적는다. 상품별 실제 포장 가격은 별도로 표시한다. 현재 주문 저장은 기존 거래처 상품 포장에 해당하는 환산 단가/수량을 사용한다. 다른 몰의 실제 포장 개수를 올림한 결제 총액을 뜻하지 않는다. 실제 쇼핑몰 주문/결제는 하지 않는다.
- 홈과 발주는 가게·서버 오늘·추천 id로 분리된 화면 초안을 공유한다. 비교 끔/오래된 가격/배송 미확인은 원래 거래처로 돌아가며 같은 수량의 기준 합계에서 차액을 계산한다. 0 이하 차액은 절약으로 표현하지 않는다.
- 주별 가격은 서버 `PriceHistoryService`와 같은 7일 구간(마지막 = StoreClock today−6일부터 today)이다. 추천 응답의 `runDate`로 구간을 계산한다. 달력 주차 문구는 구간 마지막 날의 월·7일째 순번이며 실제 시작/끝 날짜도 함께 보인다. 날짜 없는 기존 목은 상대 주차를 유지한다.
- 꺾은선은 SVG 좌표를 사용하고 점은 CSS 픽셀 원으로 분리한다. 축/눈금, 판매처 선택 범례, 포인터·탭·focus·방향키 선택과 날짜/가격 두 줄 상태를 제공한다. 빈 칸은 연결하지 않는다.

## 대안과 한계

전역 표에 시연 가격을 넣는 방법은 테넌트 격리를 깨므로 제외했다. FE에 가격을 하드코딩하는 방법은 실제 API·반복가입 흐름을 검증하지 못한다. 실제 몰 포장으로 주문 저장 구조를 바꾸면 입고·재고·발주 전반의 포장 스냅샷 설계가 필요하므로 이번 비교 범위에서는 기준 수량 환산 계약을 유지한다. 화면 초안은 현재 브라우저의 앱 실행 동안 공유하며 서버 발주서 저장을 대체하지 않는다.
