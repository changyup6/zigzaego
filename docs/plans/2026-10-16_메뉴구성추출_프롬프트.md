# 메뉴 구성 추출 · 재료 분류 프롬프트 (S15P31A308-99 · 100)

> 온보딩 분석 job([설계 2.4](2026-10-14_자동세팅_입고_예측_설계.md))의 "구성 추출"과 "분류 · 초기값" 단계에 쓸 프롬프트 · 응답 형식 · 범용 재료표 · 질문 규칙 · 채점 스크립트.
> 백엔드(S15P31A308-95)는 `ai/prompts/onboarding/` 과 `ai/seed/ingredient_catalog.csv` 를 그대로 복사해 쓴다.
> **데모 출력은 GMS 호출 결과가 아니라 Claude 가 프롬프트대로 손으로 쓴 것이다.** F1 · 토큰 수는 아직 재지 않았다.

## 1. 흐름

```
메뉴 목록 ─(menu_extraction.md, 묶음 호출)→ 메뉴별 구성요소 + mult
구성요소 이름 ─ 범용 재료표에 있음 → 표 값 (종류 · 단위 · 보관 · 1인분 · 확신도)
             └ 없음 ─(ingredient_classify.md)→ LLM 분류
분류 결과 ─(questions.py 규칙)→ 객관식 질문
```

## 2. 형식

| 파일 | 내용 |
|---|---|
| `ai/prompts/onboarding/menu_extraction.md` | `## system` · `## user` 두 절. user 의 `{{menus_json}}` 를 `[{"name","description","price"}]` 로 바꾼다 |
| `menu_extraction.schema.json` | `{"menus":[{"menu","kind":MAIN·SET·OPTION,"duplicateOf":문자열·null,"components":[{"name","role","mult"}]}]}` |
| `ai/prompts/onboarding/ingredient_classify.md` | user 의 `{{ingredients_json}}` 를 표에 없는 재료 `[{"name","role","menus"}]` 로 바꾼다 |
| `ingredient_classify.schema.json` | `{"items":[{"name","kind":BOM·ONE_TO_ONE,"unit":G·ML·EA,"storageType","perServing","confidence","shelfLifeDays"}]}` |
| `ai/seed/ingredient_catalog.csv` | 범용 재료표 76개. `name,aliases,kind,unit,storage_type,per_serving,confidence,shelf_life_days`. 값은 상식 기반 추정 ([seed/README](../../ai/seed/README.md)) |

- 스키마는 OpenAI json_schema strict 에 넣을 수 있는 부분집합만 쓴다: 모든 object 가 `additionalProperties: false` 이고 모든 칸이 `required`, null 허용은 `type: ["string","null"]`. `$schema` 키는 넣지 않는다 (strict 호환이 불확실).
- 프롬프트에는 가게 이름 · 재료명을 쓰지 않는다. 예시는 "○○ 소스" 같은 자리표시로만 (테스트가 재료표 이름 · 별칭이 프롬프트에 없는지 검사).
- 유통기한 (설계 5.3 "유통기한 기본값은 온보딩 때 LLM이 재료명으로 채운다"): 재료표 `shelf_life_days` · 분류 출력 `shelfLifeDays` 에 재료별로 개봉 전 업소 보관 기준 일수(1 이상 정수, 보수적 추정)를 둔다. 보관 방식 표(101)의 값은 재료별 값이 없을 때만 쓰는 후보값이다.
- 조합 규칙 (평가 지표 정의 §2.1): 소스는 원재료로 쪼개지 않고 "○○ 소스" 한 줄(SAUCE), 더블은 단백질 mult 2, 세트는 메뉴 이름 대신 구성 메뉴의 재료를 직접 나열하고 고를 수 있는 구성이면 공통 재료만.

## 3. 질문 규칙 (`ai/src/weglee_ai/onboarding/questions.py`, 백엔드 Java 구현의 기준)

- 대상: 분류 BOM · 소스가 아닌 역할 · 확신도 < 0.7
- 재료당 1개 (여러 메뉴에 걸려도 1개)
- 보기: 가운데 = 초기값을 간격으로 반올림(최소 한 간격), 양옆 = 초기값 × 0.8 · × 1.2 를 같은 간격으로 반올림. 간격은 초기값 크기로 — G · ML: 50 이상 10, 10 이상 5, 그 아래 1 / EA: 3 이상 1, 그 아래 0.5. 양옆이 가운데와 겹치면 가운데 ± 간격, 아래 보기가 0 이하면 가운데의 절반(간격 반올림, 최소 한 간격). 예: 5ml → 4 · 5 · 6, 14g → 10 · 15 · 20, 1개 → 0.5 · 1 · 1.5, 180g → 140 · 180 · 220. 보기는 소수일 수 있다(정수면 정수로 낸다)
- 상한: 메뉴 30개 이하 10개, 넘으면 floor(10 × 메뉴 수 / 30) (평가 지표 정의 §2.2 "이하", 예: 31개 → 10 · 44개 → 14 · 45개 → 15). 확신 낮은 순 → 걸린 메뉴 많은 순 → 이름 순

## 4. 데모 결과

입력은 `docs/spec/PRODUCT.md` 공개 메뉴 7개 + 프론트 목 데이터의 "더블 불고기 파스타볼" (`ai/prompts/onboarding/examples/`).
`python scripts/onboarding/demo_questions.py` (ai 폴더, `PYTHONPATH=src`) 출력:

```
메뉴 8개 · 재료 13개 (재료표 7 · LLM 분류 6)
  치킨 알리오 파스타볼 (4): 파스타면, 알리오 올리오 소스, 닭고기, 파르메산 치즈
  불고기 들기름 파스타볼 (3): 파스타면, 들기름 소스, 불고기
  불고기 토마토 라구 파스타볼 (4): 파스타면, 토마토 라구 소스, 불고기, 파르메산 치즈
  치킨 까르보나라 파스타볼 (5): 파스타면, 까르보나라 소스, 닭고기, 베이컨, 파르메산 치즈
  새우 매콤크림 파스타볼 (3): 파스타면, 매콤 크림 소스, 새우
  위글리 세트 (3): 파스타면, 브레드 스틱×2, 음료
  브레드 스틱 2개 (1): 브레드 스틱×2
  더블 불고기 파스타볼 (2): 파스타면, 불고기×2
질문 5개 (상한 10개)
  1. 파스타면 1인분 [G] 보기 80 / 100 / 120 · 확신 0.5 · 메뉴 7개
  2. 불고기 1인분 [G] 보기 100 / 120 / 140 · 확신 0.5 · 메뉴 3개
  3. 닭고기 1인분 [G] 보기 100 / 120 / 140 · 확신 0.5 · 메뉴 2개
  4. 새우 1인분 [EA] 보기 4 / 5 / 6 · 확신 0.5 · 메뉴 1개
  5. 베이컨 1인분 [G] 보기 25 / 30 / 35 · 확신 0.6 · 메뉴 1개
```

- 설계 2.6 의 질문 예(면 · 단백질 3종 · 까르보나라 베이컨)와 같은 재료가 나온다. 크림 소스 베이스는 소스라 질문하지 않는다.
- 재료표의 파스타면 초기값은 건면 기준 100g 이다. 위글리처럼 다른 면을 쓰는 가게는 질문 답으로 바뀐다.
- 세트의 파스타볼은 고를 수 있는 구성이라 공통인 파스타면만, 사이드는 같은 목록의 유일한 사이드인 브레드 스틱으로 적었다.

## 5. 아직 못 잰 것

| 무엇 | 기준 | 잴 수 있는 조건 |
|---|---|---|
| 재료 구성 F1 (지라 99) | ≥ 0.85 | 위글리 실제 레시피(S15P31A308-13) + GMS 실제 호출 결과 |
| 묶음 호출 토큰 수 (지라 99) | — | GMS 키 |
| 위글리 질문 수 (지라 100) | 메뉴 30개 이하 10개 | 위글리 전체 메뉴 목록 (저장소에 공개 7개만) + GMS |
| 답변 후 1인분 MAPE (지라 100) | ≤ 15% | 13번 정답 레시피 + 사장님 실제 답 |

조건이 갖춰지면 한 번에 잰다.

```bash
cd ai
PYTHONPATH=src python scripts/onboarding/score.py <job result_json 파일> <정답 csv>
```

정답 CSV 는 `menu,ingredient,qty,unit,aliases` (별칭 `;` 구분, 소스 원재료 · 주기형 품목 제외). result_json 에 `answers`(사장님 답)가 있으면 답변 후 MAPE, 없으면 초기값 기준이라고 함께 찍는다.
