# 메뉴 사진 표시 구현 계획

관련 일감: S15P31A308-129. 결정 #45의 수집 메뉴 사진을 레시피 목록·상세에서 표시한다.

## 구조

- `menu.photo_url`에 대표 사진 URL 한 개를 nullable로 저장한다. 원본은 수집 출처에서 읽는다.
- 온보딩 수집 → 분석 초안 → 확정 저장 → 메뉴·레시피 응답 → 프론트 탭으로 같은 URL을 전달한다.
- 사진 없는 이전 응답·분석 초안과 호환한다. 재확정 때 사진이 없으면 기존 사진을 유지한다.
- 예전 분석 캐시의 사진은 동일 플레이스의 메뉴 캐시로만 보완하고 외부 수집은 추가하지 않는다.
- 사진 URL은 HTTP(S) 주소만 허용하며 프론트 서버에서 이미지를 프록시하지 않는다.
- 화면의 기존 썸네일 크기를 유지하고 로딩 오류는 기존 아이콘으로 대체한다.

## 실행·검증

- [x] 메뉴별 사진 전달과 이전 응답 호환에 대한 프론트 실패 테스트 확인.
- [x] 온보딩 확정·메뉴 조회·두 가게 격리에 대한 백엔드 실패 테스트 확인.
- [x] V24 마이그레이션, 엔티티·온보딩 초안·응답에 사진 URL 연결.
- [x] 목록·상세 썸네일의 실제 이미지·실패 대체 표시 연결.
- [x] API 계약·ERD·ADR·결정 로그 갱신.
- [x] 프론트 테스트·lint·build, 백엔드 관련 통합 테스트 실행.
- [x] 모바일·데스크톱 사진 표시, 메뉴 전환, 사진 없음·실패를 브라우저로 확인.

## 적용 범위

현재 체크아웃의 사용자 변경은 보존한다. 서버 최신 마이그레이션이 V23임을 확인했으므로 V24를 사용한다.
스테이징 배포·Jira 상태 변경은 구현 결과와 별개이며 이 계획에 포함하지 않는다.

검증 결과: 프론트 111개 테스트·lint·build 통과, 백엔드 관련 40개 통합 테스트 통과.
브라우저에서 375px 모바일·데스크톱 사진 표시·메뉴 전환·사진 없음·이미지 404 대체 표시를 확인했다.
기존 시연 메뉴 5개의 사진 backfill SQL은 로컬 `ai/data/demo-demo/photos-backfill.sql`에 준비했다.
배포 뒤 V24와 함께 적용할 대상 데이터 파일이며, 가게·메뉴 ID·이름이 일치할 때만 사진을 채운다.

최신 develop의 RecipeBookResponse 이름과 온보딩 재생 경로에 맞춰 통합했다. 캐시 사진 복원 단위 테스트 3개를 포함해 관련 40개 테스트가 통과했다.
