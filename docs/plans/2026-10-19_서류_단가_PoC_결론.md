# 서류 → 품목 단가 PoC 결론 (S15P31A308-109)

> 사장님이 받는 매입 서류(거래명세서 · 영수증 · 세금계산서 등)만으로 **품목별 단가 데이터**를 모으는 제품이 되는지 공개 샘플로 판정한 개인 실험의 결론.
> **판정: 공개 샘플 기준 "불가" 쪽.** 다만 판정을 가르는 거래명세서 실물이 5장뿐이라 "증명도 반증도 못 했다"가 정확한 말이다.
> 숫자 출처: 개인 실험 저장소(팀 저장소 밖) `feat/doc-poc` 가지, 보고서 `reports/poc_docs.md`(커밋 `bc1f937`). 검사기 보강 `c1951d8` · `4b77cc0` 은 숫자를 바꾸지 않았다.
> 이 문서는 결론만 옮긴다. 결정(`docs/DECISIONS.md`)을 바꾸지 않는다.

## 1. 질문

"사장님 서류 사진 · 파일을 받으면, 사장님이 실제로 사는 품목의 단가를 얼마나 채울 수 있나?"

- **커버리지** = 서류 종류마다 (사용 빈도 가중치 × 정보 완전성 × 추출률) 를 더해 가중치 합으로 나눈 값.
  - **정보 완전성**: 채워진 실물 샘플 중 품목명 · 수량 · 단가가 모두 적혀 있는 비율 (서류에 애초에 단가가 있나)
  - **추출률**: 적혀 있는 줄을 기계가 맞게 읽는 비율 (OCR · 파일 파싱이 읽어 내나)
  - **사용 빈도 가중치**: 종류별 예상 사용 빈도(가정). 기본 · 균등(전부 1) · 상위 집중(1 · 2순위 종류 10, 나머지 1) 세 세트로 계산
- 수집 방안은 사진 · 파일 · 연동(세금계산서 연동 서비스) · 카톡 텍스트 4개 중 **3개 이하 조합의 최고값**을 쓴다.
- 판정 규칙(결과 보기 전 고정): **가능** = 기본 60% 이상이고 다른 두 세트 50% 이상 / **조건부** = 기본 40~60%, 또는 기본 60% 이상인데 다른 세트 하나라도 50% 미만 / **불가** = 기본 40% 미만.

## 2. 한 방법

| 재료 | 양 | 쓴 곳 |
|---|---|---|
| 웹에서 모은 공개 서류 이미지 (10종) | 304장, 그중 채워진 실물 98장 | 정보 완전성 · OCR 실측 |
| 라벨 | 304장 전수, 별도 사람이 무작위 30장 독립 재검수 2회 (채워짐 · 거래처 단가표 · 그 외 3분류 일치 0.900, 품목 · 수량 · 단가 읽힘 일치 0.933) | 정보 완전성 |
| 로컬 OCR (PaddleOCR + 직접 만든 파서) | 실제 서류 58장 · 정답 428줄 | 추출률 실측 |
| 합성 거래명세서 (훼손 단계 0~5) | 단계당 20장 | 거래명세서 중간 추정(**합성추정**)에만 |
| 식봄 시세 (2026-10-07 하루치) | 핵심 품목 10개 | 오독 검사 · 서류 0장 시작 |
| 수집 방안 웹 조사 | 7+1개 방안, 공식 문서 직접 확인 표시 | 연동 · 파일 경로 판단 |

- 표본이 작은 종류는 한 값으로 말하지 않고 **하한**(나쁜 쪽 끝)과 **상한**(좋은 쪽 끝)으로 계산했다. 5~29장인 종류는 95% 신뢰구간의 양 끝을 쓴다(거래명세서 3/5 → 0.231~0.882).
- 실제 사장님 서류는 **한 장도 없다.** 모든 숫자는 "공개 샘플 수준까지 확인, 현장 미확인"이다.

## 3. 결과 숫자

판정에 쓰는 값 (기본 시나리오 = 로컬 OCR 실측, 순서는 기본 · 균등 · 상위 집중 가중치):

| 경계 | 커버리지 | 판정 |
|---|---|---|
| 하한 | 18.1% · 11.9% · 24.0% | 불가 |
| 합성추정 · 깨끗한 사진 위주 | 27.7% · 17.8% · 38.9% | 불가 |
| 합성추정 · 보통 | 25.2% · 16.4% · 34.0% | 불가 |
| 합성추정 · 훼손 위주 | 21.4% · 14.4% · 26.9% | 불가 |
| 상한 | 29.6% · 33.5% · 34.3% | 불가 |

조건이 붙는 실측값:

- **영수증 OCR 줄 정확도 0.603** (개선 전 0.168). 같은 표본을 보면서 파서를 고쳤으므로 과대평가 가능성이 크고, 대부분 마트 · 편의점 소비자 영수증이다.
- **거래명세서 OCR 줄 정확도 0.125** — 정답이 있는 실물 1장 8줄. 표본이 작다.
- **단가 10배 오독 검사**: 식봄 시세 범위(중앙값의 1/3~3배)로 10배 오류 122줄 중 106줄(86.9%)을 막았지만, 정상 단가를 잘못 막은 줄도 24줄. 사전 기준 90%에 못 미친다.
- **서류 0장으로 시작**: 핵심 품목 10개 모두 식봄 시세 카드로 첫 화면을 채울 수 있다(내 가게 단가가 아니라 시세 기본값).

## 4. 판정과 그 근거

**판정 줄**: `VERDICT 하한=불가 합성추정=불가 상한=불가`.

1. **상한조차 40%에 못 미친다.** 좋은 쪽 끝으로 잡아도 기본 29.6%, 세 세트 중 가장 높은 값도 34.3%다. 상한 규칙을 다르게 해석한 두 경우(기본 세트 39.7% · 22.8%)와 거래명세서에 영수증 OCR 값 0.603 을 넣은 경우(기본 세트 37.5%)도 모두 불가다.
2. **세금계산서 · 거래원장 · 발주서 · 카톡은 단가 기여가 0이다.** 공개 샘플에서 단가가 읽힌 실물이 없거나 단가 칸이 과반 비어 있어 상한도 0으로 뒀다. 전자세금계산서의 품목 · 수량 · 단가는 법상 필수 기재사항이 아니다. 세금계산서는 단가 출처가 아니라 총액 대조용이다.
3. **가장 큰 몫인 거래명세서를 로컬 OCR 이 거의 못 읽는다(0.125).** 정보 완전성이 높아도 추출률을 곱하면 기여가 작다.

**합성추정이 상한보다 클 때가 있다** (상위 집중 · 깨끗 위주 38.9% > 상한 34.3%). 계산 오류가 아니다. 상한은 거래명세서 추출률에 실측 0.125 를, 합성추정은 합성 OCR 0.712 를 쓰기 때문이다. 그래서 합성추정은 "하한과 상한 사이"가 아니라 **추출률을 다르게 가정한 별도 추정**으로 읽는다. 어느 쪽이든 40% 미만이라 판정은 같다.

**"반증"이라고 하지 않는 이유**: ① 사진을 이미지 읽는 AI(멀티모달 LLM)로 읽는 경로는 시험하지 않았다. 추출률 0.9를 **가정**하면 상한이 47.9% · 43.2% · 69.0% 로 **조건부**가 된다. ② 거래명세서 OCR 값이 1장 8줄에서 나왔다.
즉 판정을 가르는 것은 **거래명세서 사진을 무엇으로 얼마나 정확히 읽느냐**다.

## 5. 한계와 남은 것

한계:

- 채워진 식자재 서류 67장 중 61장이 소비자 영수증이라 식당 매입을 대표하는지 모른다.
- 결과를 본 뒤 바꾼 규칙이 7개 있다(보고서에 이유와 함께 기록). 판정 기준값 60 · 50 · 40% 는 한 번도 바꾸지 않았고, 하한은 내내 불가였다.
- "영수증 3장으로 온보딩" 측정(핵심 품목 커버리지 평균 6.6%)은 공개 샘플에 파스타 가게 품목이 거의 없어서 나온 값이다. **팀장 의견의 기각이 아니라 측정 설계의 한계**다.

남은 것 (아직 안 함):

1. 검토 의견에 인용된 설문 숫자를 설문 원자료와 대조
2. 가상 샘플 이미지에 찍힌 사업자번호 가리기
3. 새로 받은 사본에서 재현 — 지금은 git 에 없는 시세 파일 · 화면 데이터 파일에 기대고 있어 새 사본에서는 다시 돌아가지 않는다

현장에서 받으면 판정이 가장 많이 움직이는 자료: **거래명세서 사진 10~20장**(최근 1~3개월, 거래처 2~3곳, 손글씨 · 감열지 그대로) → 같은 달 세금계산서 1~2장 → 앱 주문내역 · 카톡 단가 메시지 캡처 → 식자재 영수증 10장.

## 6. 우리 제품에 주는 뜻

- **입고 OCR([결정 #27](../DECISIONS.md))과 질문이 다르다.** 이 PoC는 "서류만으로 단가 데이터베이스를 채울 수 있나"를 물었다. 입고 화면에서 사장님이 확인하는 OCR 은 사장님이 고칠 기회가 있으므로 이 판정이 그대로 적용되지 않는다.
- **단가는 서류 하나에 기대지 않는다.** PoC 결과로 보면 서류 0장일 때 식봄 시세로 채우고, 서류가 들어오면 내 가게 단가로 덮는 순서가 안전하다. 세금계산서는 총액 대조용으로만 본다.
- **109 OCR 비교가 바로 이 빈칸을 잰다.** 109는 같은 사진을 CLOVA OCR + LLM(방식 A)과 멀티모달 LLM 단독(방식 B)으로 읽어 줄 정확도를 낸다([평가 지표 정의 §3.1](평가_지표_정의.md)). PoC에서 시험하지 못한 "이미지 읽는 AI 경로"의 거래명세서 추출률이 그 결과다.
  - 109의 거래명세서 줄 정확도가 0.9 근처면 위 가정 계산상 상한이 조건부로 올라간다. 0.125 근처면 불가가 굳는다.
  - 단, 109의 채점 사진은 **가상 샘플**이라 PoC의 합성추정과 같은 등급의 증거다. 현장 판정은 실제 거래명세서가 들어온 뒤에 한다.
  - 두 실험의 줄 정확도 정의는 비슷하지만 같지 않다(PoC: 품목명 유사도 0.6 이상 + 수량 · 단가 · 금액 일치, 앞쪽 줄 위주 정답 / 109: 편집 거리 짝짓기 + 품목명 · 수량 · 단가 정확 일치). 숫자를 그대로 겹쳐 비교하지 않는다.
