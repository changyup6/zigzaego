# 가격 지수 정의 (가격 연동 발주의 입력)

기준일: 2026-10-15 · 지라 S15P31A308-58 · 상위 문서: [3주 개발 계획](3주_개발_계획.md) 4.8절, [자동 세팅 · 사진 입고 · 예측 설계](2026-10-14_자동세팅_입고_예측_설계.md) 4.3절 · DECISIONS #12

3주 계획 4.8절의 식(8주 중앙값 · θ · R 배수)은 그대로 쓴다. 이 문서는 그 식이 정하지 않은 자리를 채운다: 무엇을 단가 이력으로 치나, 포장이 다른 단가를 어떻게 비교하나, 이력이 모자라거나 튈 때 어떻게 하나.

## 1. 정의식

```
단위 단가(행) = price_history.price ÷ supplier_product.base_qty_per_pack     (원 / 기준 단위 g · ml · 개)
              base_qty_per_pack 이 비어 있으면 그 행은 쓰지 않는다

기준 단가(i)  = 재료 i 의 현재 단가 날짜 직전 8주(현재 단가 날짜 − 56일 ~ 하루 전) 단위 단가 중앙값
              현재 단가 날짜는 넣지 않는다
현재 단가(i)  = 재료 i 의 가장 최근 단위 단가 (오늘 포함, 최근 8주 안)
가격 지수(i)  = 현재 단가(i) ÷ 기준 단가(i)

가격 수준     = 비쌈  if 가격 지수 ≥ 1 + θ
              = 쌈    if 가격 지수 ≤ 1 − θ
              = 보통  그 외
```

## 2. 기본값

| 항목 | 기본값 | 근거 |
|---|---|---|
| θ (보통으로 보는 폭) | 0.10 | 3주 계획 4.8절 |
| 비쌀 때 R 배수 | × 0.5 (최소 1일) | 3주 계획 4.8절 |
| 쌀 때 R 배수 | × 2.0 (유통기한 − L 일치 · `max_order_qty` 를 넘지 않음) | 3주 계획 4.8절 |
| 기준 기간 | 현재 단가 날짜 직전 8주 (56일) | 3주 계획 4.8절. 현재 단가 날짜는 기준에 넣지 않는다 |
| 최소 이력 | 기준 기간 안 단가 3건 (현재 단가 날짜 제외) | 3주 계획 4.8절 "3건 미만이면 조정 없음" |
| `price_sensitive` | 보관 방식별 | [보관 방식별 기본값](2026-10-15_보관방식_기본값.md) (S15P31A308-101, MR !20 머지됨) |

## 3. 정하지 않았던 자리

| 상황 | 규칙 | 이유 |
|---|---|---|
| 어떤 기록을 이력으로 치나 | `price_history.source` 가 `RECEIVE` · `DOC` · `MANUAL` 인 행만. **`MARKET`(시세) 은 빼고, 식봄 · 쿠팡 비교 가격(DECISIONS #37)도 넣지 않는다** | 가격 지수는 "이 가게가 실제로 산 값"이 평소보다 비싼가를 본다(DECISIONS #12). 시세 · 다른 몰 가격이 섞이면 사지도 않은 값으로 발주가 흔들린다 |
| 과거 영수증(PAST) | 단가 이력으로 **쓴다**. 영수증 날짜를 `observed_at` 으로 | 설계 4.3절: PAST 도 price_history 에 기록. 가입 첫날 과거 영수증을 올리면 8주 이력이 바로 찬다 |
| 포장이 다른 상품 | 단위 단가(원/기준 단위)로 바꿔 비교. 같은 재료의 여러 상품 · 여러 거래처를 한 이력으로 합친다 | 대파 1단과 대파 1kg 이 섞여도 같은 줄에 선다. 거래처를 바꿔도 이력이 끊기지 않는다. **3주 계획 4.8절은 "주 거래처 상품" 단가 이력인데, 이 문서 · 구현은 재료의 모든 상품 · 거래처를 합친다 — 범위가 다르다.** 더 싼 거래처로 바꾸기만 해도 "쌈" 이 되어 R × 2 가 될 수 있다 |
| 0원 이하 단가 | 그 행은 빼고 센다 (`PriceIndexCalculator.isUsable` · SQL `price > 0`) | 실제로 산 값으로 볼 수 없다. 관측 · 주별 칸 · 지수가 같은 행을 보도록 코드와 SQL 이 같은 조건을 쓴다 |
| `base_qty_per_pack` 이 빈 상품 | 그 상품 행은 빼고 센다 | 단위를 모르면 비교할 수 없다. 첫 입고 확인 때 채워진다(설계 3절) |
| 같은 날 여러 건 | 그날 단위 단가의 중앙값 1건으로 센다 | 영수증 한 장에 같은 재료가 여러 줄이면 이력 건수가 부풀려진다 |
| 이력 3건 미만 | 가격 지수 = 1(보통), R 조정 없음. 이유 문장에 가격 줄을 넣지 않는다 | 3주 계획 4.8절 |
| 현재 단가가 8주보다 오래됨 | 가격 지수 = 1 | 최근에 산 적이 없으면 "지금 비싸다"를 말할 수 없다 |
| 튀는 값 | 따로 거르지 않는다 | 기준은 중앙값이라 한두 건의 튀는 값에 흔들리지 않는다. 현재 단가가 튀면 사장님이 입고 확인 화면에서 단가를 고친다 |
| 주기형 재료 | 같은 규칙. 단, `price_sensitive` 기본 OFF (보관 방식 없음) | 보관 방식별 기본값 문서 |

## 4. 확인 예 (3주 계획 4.8절 예를 단위 단가로)

파스타면, 기준 단위 g. 최근 8주 단위 단가(원/g) 4.0 · 3.9 · 4.1 · 4.0 · 4.2 → 기준 단가 4.0원/g.

| 오늘 산 값 | 단위 단가 | 지수 | 수준 | R=2일일 때 R' |
|---|---|---|---|---|
| 5kg 포대 23,000원 | 4.6원/g | 1.15 | 비쌈 | 1일 |
| 1kg 4,100원 | 4.1원/g | 1.025 | 보통 | 2일 |
| 5kg 포대 17,000원 | 3.4원/g | 0.85 | 쌈 | 4일 (유통기한 안에서) |
| 이력이 2건뿐 | — | 1 | 보통 | 2일 |

## 5. 조정

θ · 배수는 제안값이다. 위글리 영수증으로 단가 이력이 쌓이면 재료별로 "지수가 θ 를 넘는 날이 얼마나 자주 오나"를 보고 한 번 조정한다. 너무 자주 넘으면(주 2회 이상) 추천이 매번 흔들리니 θ 를 올린다.
