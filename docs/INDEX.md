## 문서 관리 규칙

### 1. 여기가 원본이다

문서는 **코드와 같은 GitLab 레포**에 있습니다. Jira에도, 메신저에도, 개인 노션에도 설계를 적지 마세요. 두 곳에 있으면 반드시 한쪽이 틀려집니다.

- **문서(md)** = 왜 이렇게 만드는가 · 어떻게 만드는가
- **Jira** = 지금 누가 무엇을 하고 있는가 (상태만)

Jira 티켓 설명에는 **문서 경로만** 넣습니다. 내용을 복사하지 않습니다.

### 2. 결정이 바뀌면 같은 MR에서 문서를 고친다

stale을 막는 유일한 장치입니다. MR 템플릿 체크박스에 들어 있습니다.

```markdown
- [ ] 이 변경이 설계 결정을 바꾸나요?
      → 예: DECISIONS.md에 항목 추가 + 관련 문서 수정 (이 MR에 포함)
      → 아니오: 그대로 진행
```

문서 수정 없는 설계 변경 MR은 승인하지 않습니다.

### 3. 최종 수정일을 손으로 적지 않는다

손으로 적은 날짜는 반드시 틀려집니다. git이 알려줍니다.

```bash
git log -1 --format='%cd %an' -- docs/plans/3주_개발_계획.md
```

### 4. 문서 하나는 200줄을 넘기지 않는다

넘으면 주제가 두 개 섞인 것입니다. 쪼개세요. 긴 문서는 토큰도 많이 쓰고, 읽는 사람도 AI도 위치를 못 찾습니다.

**예외**: `plans/3주_개발_계획.md`와 `spec/아키텍처_바이블.md`는 프로젝트 시작 전에 쓰인 문서라 깁니다. 내용이 바뀌는 절부터 떼어내고, 그 전까지는 **절 번호로 참조**합니다.

### 5. 결정은 지우지 말고 덮어써라

`DECISIONS.md`는 append-only입니다. 뒤집힌 결정도 남겨야 "왜 이렇게 됐지"에 답할 수 있습니다.
